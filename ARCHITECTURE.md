# Архитектура проекта: AI TZ Analyzer (Streamlit)

## 1. Обзор системы
Приложение на Streamlit для парсинга файлов ТЗ (.pdf, .docx), анализа текста через API GPTunneL с выбором моделей и экспорта результатов в .xlsx.

├── requirements.txt

## 4. Формат обмена данными (ИИ -> Excel)

Модель обязана вернуть **только** JSON-объект (без markdown-обрамления ```json, без пояснений до/после). Системный промпт (`config.DEFAULT_SYSTEM_PROMPT`) явно это требует.

### 4.1. Схема ответа модели

```json
{
  "items": [
    {
      "item_number": 1,
      "name": "Диван двухместный",
      "characteristics": [
        "Материал обивки: искусственная кожа",
        "Цвет: чёрный"
      ],
      "max_width_mm": 1700,
      "max_depth_mm": 700,
      "max_height_mm": 850,
      "quantity": 10
    },
    {
      "item_number": 2,
      "name": "Стул для столовой",
      "characteristics": [
        "Материал каркаса: металл",
        "Материал сиденья: пластик",
        "Цвет: серый"
      ],
      "max_width_mm": null,
      "max_depth_mm": null,
      "max_height_mm": 870,
      "quantity": 120
    },
    {
      "item_number": 3,
      "name": "Пуф",
      "characteristics": [
        "Форма: квадратная",
        "Материал обивки: ткань"
      ],
      "max_width_mm": 600,
      "max_depth_mm": 600,
      "max_height_mm": 450,
      "quantity": 5
    }
  ]
}
```

### 4.2. Описание полей `items[i]`

| Поле | Тип | Обязательное | Описание |
|---|---|---|---|
| `item_number` | `int` | да | Номер позиции по порядку, присваивается моделью последовательно (1, 2, 3, …) |
| `name` | `string` | да | Наименование позиции/изделия по ТЗ (например, «Диван двухместный», «Стул для столовой») |
| `characteristics` | `array[string]` | да | Список характеристик позиции по ТЗ (материал, цвет, форма и т.п.), каждая характеристика — отдельная строка списка |
| `max_width_mm` | `int \| null` | нет | Максимальная ширина изделия в миллиметрах; `null`, если в ТЗ не указана |
| `max_depth_mm` | `int \| null` | нет | Максимальная глубина изделия в миллиметрах; `null`, если в ТЗ не указана |
| `max_height_mm` | `int \| null` | нет | Максимальная высота изделия в миллиметрах; `null`, если в ТЗ не указана |
| `quantity` | `int` | да | Требуемое количество изделий данной позиции |

Если модель не заполнила какое-то поле — `utils/excel_generator.py` подставляет `None` (пустая ячейка в Excel), а не выбрасывает исключение, чтобы не терять весь результат из-за одного неполного элемента. Поле `characteristics` — единственное поле-массив: при сериализации в Excel список объединяется в одну ячейку (каждая характеристика с новой строки внутри ячейки), чтобы сохранить читаемость и не плодить динамическое количество колонок.

### 4.3. Конвейер обработки ответа

```
raw_response (str, сырой текст от API)
        │
        ▼
_extract_json_block()   — regex вырезает { ... }, даже если модель
                           обернула ответ в ```json ... ``` или добавила текст вокруг
        │
        ▼
json.loads()             — парсинг в dict; ResponseParsingError при невалидном JSON
        │
        ▼
data["items"]             — список требований; ResponseParsingError, если отсутствует/пуст
        │
        ▼
pd.DataFrame(items)       — сырой DataFrame из списка dict
        │
        ▼
reindex по EXPECTED_COLUMNS — гарантирует фиксированный порядок и полный набор колонок
        │
        ▼
result_df (pd.DataFrame)  — источник правды: рендерится в st.dataframe/data_editor
        │                     и сериализуется в xlsx
        ▼
excel_bytes (bytes)       — итоговый файл для download_button
```

### 4.4. Результирующая таблица в Excel (шаблон-ориентированная генерация)

Структура итогового xlsx (колонки, их порядок, русские заголовки, группы-шапки, формулы, служебные строки сверху и снизу) целиком описывается JSON-шаблоном `templates/excel_template.json`. Шаблон загружается в `config.py` в константу `EXCEL_TEMPLATE`, а из него производятся `EXPECTED_COLUMNS`, `COLUMN_LABELS` и `COLUMN_GROUPS`. `utils/excel_generator.py` не содержит упоминаний конкретных полей (ширина, объём и т. п.): он читает шаблон и строит файл по нему. Чтобы добавить, убрать или переставить колонку, изменить формулу или подпись, достаточно отредактировать JSON — код менять не нужно.

#### 4.4.1. Структура шаблона

Корневые ключи:

| Ключ | Назначение |
|---|---|
| `sheet_name` | Название листа |
| `top_rows[]` | Строки над шапкой с ячейкой ручного ввода: `id`, `label`, `input_column` (колонка, над которой стоит ячейка ввода) |
| `columns[]` | Колонки таблицы в порядке отображения |
| `footer_rows[]` | Строки под таблицей (итоги). В одной строке может быть несколько итоговых ячеек в разных колонках: `label`, `cells[]` (список `{column, formula, number_format?}`), `label_column?` (см. ниже) |

Поля колонки `columns[i]`:

| Поле | Обязательное | Описание |
|---|---|---|
| `key` | да | Внутреннее имя колонки (ключ в JSON ответа ИИ и в DataFrame) |
| `label` | да | Заголовок в Excel (русский) |
| `source` | да | `ai` — значение приходит из ответа модели; `manual` — колонка остаётся пустой, пользователь заполняет её в Excel; `formula` — в ячейку пишется формула из поля `formula` |
| `formula` | для `formula` | Формула Excel с плейсхолдерами (см. ниже) |
| `group` | нет | Общий заголовок над соседними колонками с одинаковым значением (объединение ячеек шапки по горизонтали) |
| `type` | нет | `"list"` — значение является массивом, каждый элемент выводится отдельной строкой |
| `item_level` | нет (по умолчанию `true`) | Ячейка относится к позиции целиком и объединяется по вертикали, если у позиции несколько строк |
| `wrap` | нет | Перенос по словам в ячейке |
| `width` | нет | Ширина колонки (иначе подбирается автоматически) |
| `number_format` | нет | Числовой формат ячейки Excel |

Плейсхолдеры в формулах:

- `{key}` — ячейка колонки `key` в текущей строке позиции;
- `{key:range}` — диапазон данных колонки `key` (от первой до последней строки позиций);
- `{@id}` — абсолютный адрес (например, `$H$25`) ячейки с этим `id`: либо ячейки ввода из `top_rows`, либо итоговой ячейки из `footer_rows[].cells[]`. Так итоговые ячейки можно использовать в формулах других `footer_rows` (и даже колонок), в том числе ссылаться на строки ниже. Адреса итоговых ячеек вычисляются до записи формул. Циклические ссылки генератор не проверяет — это делает Excel. Пространство `id` общее для `top_rows` и `footer_rows`: повтор даёт `TemplateError`.

Буквы столбцов и номера строк вычисляются при генерации по порядку колонок в шаблоне и не хардкодятся. Неизвестный ключ в плейсхолдере приводит к `TemplateError` с понятным текстом.

Строки `footer_rows[]` (итоги под таблицей):

| Поле | Обязательное | Описание |
|---|---|---|
| `label` | да | Подпись строки |
| `label_column` | нет | Ключ колонки, где стоит подпись; по умолчанию первая колонка шаблона. Ячейки от неё до колонки, предшествующей первой итоговой ячейке, объединяются по горизонтали |
| `cells[]` | да | Итоговые ячейки строки, по одной на колонку |
| `cells[].id` | нет | Уникальный идентификатор ячейки (латиница, цифры, `_`). Позволяет ссылаться на неё как `{@id}` из других формул. Для объединённой ячейки (`end_column`) адресом служит первая ячейка |
| `cells[].column` | да | Ключ колонки, в которой стоит ячейка |
| `cells[].formula` | да (кроме `input`) | Формула Excel. Доступны `{key:range}` и `{@id}`; `{key}` в итоговых строках не допускается |
| `cells[].input` | нет | `true` — ячейка ручного ввода: формулы нет, ячейка остаётся пустой, пользователь заполняет её в Excel. Вместе с `formula` не допускается. Чтобы использовать значение в других формулах, задайте `id` |
| `cells[].value` | нет | Значение по умолчанию для ячейки с `input: true` (например, `1.2`) |
| `cells[].end_column` | нет | Ключ колонки, до которой ячейка объединяется по горизонтали (включительно); формула пишется в первую ячейку. Не может быть левее `column`, объединения в одной строке не должны пересекаться |
| `cells[].number_format` | нет | Числовой формат ячейки; если не задан, берётся `number_format` колонки |

Колонки не обязаны идти подряд: между итоговыми ячейками могут быть пустые колонки. Две ячейки одной строки не могут ссылаться на одну колонку, и ячейка не может стоять в колонке подписи или левее её. Нарушение даёт `TemplateError`. Прежний формат `value_column` + `formula` поддерживается и означает одну ячейку: `cells: [{column: value_column, formula: formula}]`.

Фрагмент шаблона (сокращённо):

```json
{
  "sheet_name": "Позиции закупки",
  "top_rows": [
    {"id": "check_count", "label": "общее количество из ЕИС →", "input_column": "quantity"}
  ],
  "columns": [
    {"key": "item_number", "label": "№", "source": "ai"},
    {"key": "sketch", "label": "Эскиз", "source": "manual", "width": 20},
    {"key": "characteristics", "label": "Характеристики по ТЗ", "source": "ai", "type": "list", "item_level": false, "wrap": true},
    {"key": "volume", "label": "Объём", "source": "formula",
     "formula": "=IF(AND(ISNUMBER({max_width_mm}),ISNUMBER({max_depth_mm}),ISNUMBER({max_height_mm}),ISNUMBER({quantity})),({max_width_mm}/1000)*({max_depth_mm}/1000)*({max_height_mm}/1000)*{quantity},\"\")"},
    {"key": "tz_price", "label": "Цена по ТЗ", "source": "manual", "group": "Вариант 1"},
    {"key": "tz_sum", "label": "Сумма по ТЗ", "source": "formula", "group": "Вариант 1",
     "formula": "=IF(AND(ISNUMBER({volume}),ISNUMBER({tz_price})),{volume}*{tz_price},\"\")"}
  ],
  "footer_rows": [
    {"label": "Итого с НДС →", "cells": [
      {"column": "tz_sum", "formula": "=ROUND({@total_tz}*1.2,2)"}
    ]},
    {"label": "Итого →", "cells": [
      {"id": "total_tz", "column": "tz_sum", "formula": "=SUM({tz_sum:range})"},
      {"column": "quantity", "formula": "=SUM({quantity:range})"},
      {"column": "volume", "formula": "=SUM({volume:range})", "number_format": "0.000"},
      {"column": "tz_sum", "formula": "=SUM({tz_sum:range})"},
      {"column": "sketch_sum", "formula": "=SUM({sketch_sum:range})"}
    ]},
    {"label": "проверка общего количества →", "cells": [
      {"column": "quantity", "formula": "=IF({@check_count}=SUM({quantity:range}),\"Всё ОК\",\"Ошибка!\")"}
    ]}
  ]
}
```

Полный актуальный список колонок — в самом файле шаблона; ниже описан результат для шаблона, поставляемого по умолчанию.

#### 4.4.2. Колонки шаблона по умолчанию

Соответствие русских заголовков внутренним полям (так выглядит шаблон, поставляемый по умолчанию; русские заголовки относятся только к Excel, на внутренние ключи JSON/DataFrame из §4.1–§4.2 они не влияют):

| Заголовок в Excel | Внутреннее поле |
|---|---|
| № | `item_number` |
| Наименование | `name` |
| Эскиз | — (служебная колонка, всегда пустая) |
| Характеристики по ТЗ | `characteristics` |
| Ширина | `max_width_mm` |
| Глубина | `max_depth_mm` |
| Высота | `max_height_mm` |
| Количество | `quantity` |
| Объём | — (вычисляемая колонка, не хранится в DataFrame/JSON) |
| Цена по ТЗ (в группе «Вариант 1») | — (служебная колонка, всегда пустая, заполняется пользователем вручную в Excel) |
| Сумма по ТЗ (в группе «Вариант 1») | — (вычисляемая колонка, не хранится в DataFrame/JSON) |
| Цена по эскизу (в группе «Вариант 2») | — (служебная колонка, всегда пустая, заполняется пользователем вручную в Excel) |
| Сумма по эскизу (в группе «Вариант 2») | — (вычисляемая колонка, не хранится в DataFrame/JSON) |
| Заполнение | — (вычисляемая колонка, не хранится в DataFrame/JSON) |

Колонка «Объём» — последняя в таблице, вычисляемая: значений для неё нет ни в ответе ИИ, ни в DataFrame, вместо этого в каждую ячейку строки-позиции при генерации xlsx записывается формула Excel (а не число), которая на лету считает объём в м³ по габаритам и количеству из ячеек той же строки. Если колонки расположены в порядке из таблицы выше (A — «№», …, E — «Ширина», F — «Глубина», G — «Высота», H — «Количество», I — «Объём»), то для строки `N` формула выглядит так:

```
=IF(AND(ISNUMBER(E{N}),ISNUMBER(F{N}),ISNUMBER(G{N}),ISNUMBER(H{N})),(E{N}/1000)*(F{N}/1000)*(G{N}/1000)*H{N},"")
```

В файле аргументы функций разделяются запятой (так формулы хранятся в OOXML); в русской локали Excel сам покажет `;`. Формула сознательно записывается с англоязычными именами функций (`IF`, `AND`, `ISNUMBER`), а не их русскими алиасами (`ЕСЛИ`, `И`, `ЕЧИСЛО`): формат `.xlsx` (OOXML) всегда хранит формулы во внутреннем представлении на английском, а локализованные названия — это только то, как Excel отображает их в интерфейсе при русской локали. `openpyxl` записывает переданную строку «как есть», без такой трансляции, поэтому формула с русскими именами функций, записанная напрямую в XML, не распознаётся Excel при открытии файла и показывается как `#ИМЯ?` — работать она начинает только если пользователь вручную зайдёт в ячейку и нажмёт Enter, заставив Excel заново распарсить её через свой локализованный UI-парсер. При открытии готового xlsx-файла Excel с русской локалью интерфейса всё равно отображает формулу пользователю в привычном виде (`ЕСЛИ`, `И`, `ЕЧИСЛО`, `;`) — меняется только то, как формула хранится в файле, а не то, как она выглядит для человека.

Адреса ячеек в формуле подставляются динамически по фактическому индексу столбцов «Ширина»/«Глубина»/«Высота»/«Количество» и номеру строки при генерации файла, а не хардкодятся, — если порядок колонок в шаблоне `excel_template.json` изменится, формула перестроится автоматически (в шаблоне она записывается плейсхолдерами `{max_width_mm}` и т. п., а не буквами столбцов). Формула проверяет функцией `ISNUMBER` (англоязычное имя, см. ниже), что все четыре величины — числа (то есть ни одна из них не была пустой ячейкой из-за `null` в ответе ИИ), и только тогда считает объём как произведение габаритов, переведённых из миллиметров в метры, на количество; иначе в ячейку выводится пустая строка `""` (визуально пустая ячейка), чтобы не путать «объём не может быть посчитан» с нулевым объёмом и не выводить лишний текст в ячейке, участвующей в дальнейших вычислениях («Сумма по ТЗ»/«Сумма по эскизу»). Для строк, объединённых по позиции (несколько характеристик), формула проставляется только в первой строке диапазона объединения, как и остальные поля уровня позиции.

#### 4.4.3. Группы «Вариант 1» и «Вариант 2»

Справа от колонки «Объём» в итоговый файл добавлены ещё четыре колонки, объединённые над ними в два общих заголовка-шапки (объединённые ячейки первой строки шапки через `merge_cells`):

- **«Вариант 1»**: «Цена по ТЗ», «Сумма по ТЗ».
- **«Вариант 2»**: «Цена по эскизу», «Сумма по эскизу».

«Цена по ТЗ» и «Цена по эскизу» — обычные пустые ячейки, как «Эскиз»: ни ИИ, ни код их не заполняют, пользователь вписывает цену вручную в Excel после получения файла (это единственные исходные данные для расчёта сумм, которых нет в ответе модели).

«Сумма по ТЗ» и «Сумма по эскизу» — вычисляемые колонки: как и «Объём», в каждую первую строку диапазона объединения позиции записывается формула Excel, а не число. В отличие от предыдущей версии, теперь эти формулы тоже проверяют операнды через `ISNUMBER` и возвращают пустую строку `""`, если «Объём» или соответствующая цена не заполнены (а не молчаливый «Объём» также пуст (`""`), поэтому проверка `ISNUMBER(I{N})` заодно защищает и от этого случая), — чтобы пустая цена или незаполненный объём давали действительно пустую ячейку, а не обманчивый `0`:

```
Сумма по ТЗ:      =IF(AND(ISNUMBER(I{N}),ISNUMBER(J{N})),I{N}*J{N},"")
Сумма по эскизу:  =IF(AND(ISNUMBER(I{N}),ISNUMBER(L{N})),I{N}*L{N},"")
```

(где `I` — фактический столбец «Объём», `J` — «Цена по ТЗ», `L` — «Цена по эскизу»; как и для формулы объёма, буквы столбцов и номер строки `{N}` вычисляются динамически по порядку колонок в шаблоне, а не хардкодятся).

Колонка «Заполнение» — крайняя правая, вычисляемая: значений для неё нет ни в ответе ИИ, ни в DataFrame. В каждую первую строку диапазона объединения позиции записывается формула, которая выводит `"ПУСТО"` только если обе суммы («Сумма по ТЗ» и «Сумма по эскизу») пусты, во всех остальных случаях (любая одна из сумм заполнена) — `"Заполнено"`:

```
=IF(AND(K{N}="",M{N}=""),"ПУСТО","Заполнено")
```

(где `K` — фактический столбец «Сумма по ТЗ», `M` — «Сумма по эскизу»; буквы столбцов и номер строки `{N}` вычисляются динамически по порядку колонок в шаблоне, а не хардкодятся). Проверка `=""` отличает пустую строку — результат формул сумм при незаполненных исходных данных — от заполненного значения, включая `0`, если пользователь явно ввёл нулевую цену.

Особенности рендера в Excel:

- Колонка «Характеристики по ТЗ» (`characteristics`) сериализуется как многострочный текст в одной ячейке (перенос строки `\n` между элементами списка), для ячейки включается перенос по словам (`wrap_text=True`), чтобы весь список характеристик был виден без обрезки.
- Пустые «Ширина» / «Глубина» / «Высота» (значение `null` в JSON) превращаются в пустые ячейки, а не в текст `"None"` или `"null"`.
- Колонка «Эскиз» ничем не заполняется автоматически — пользователь вставляет изображение вручную в Excel после скачивания файла.
- Колонка «Объём» всегда содержит формулу Excel, а не статическое значение: при ручном редактировании ширины/глубины/высоты/количества в самом xlsx-файле пользователем объём пересчитается автоматически.
- Колонки «Цена по ТЗ» и «Цена по эскизу» ничем не заполняются автоматически, так же как «Эскиз» — это ручной ввод пользователя.
- Колонки «Сумма по ТЗ» и «Сумма по эскизу» содержат формулы Excel (`Объём × цена`), которые автоматически пересчитываются при ручном вводе цены в соответствующей колонке или при редактировании габаритов/количества, влияющих на «Объём»; если «Объём» или цена не заполнены, ячейка суммы остаётся пустой, а не показывает `0`.
- Колонка «Заполнение» содержит формулу Excel, которая выводит `"ПУСТО"` только если обе суммы («Сумма по ТЗ» и «Сумма по эскизу») пусты, и `"Заполнено"`, если хотя бы одна из них заполнена; пересчитывается автоматически вместе с суммами.
- Колонка `item_number` («№») используется как стабильный ключ при редактировании через `st.data_editor` (добавление/удаление строк не должно ломать порядок остальных).

### 4.5. Обработка ошибок формата

| Ситуация | Где ловится | Поведение |
|---|---|---|
| Модель обернула JSON в текст/markdown | `_extract_json_block` | JSON извлекается regex'ом, не падает |
| Невалидный JSON | `json.loads` | `ResponseParsingError` → показывается в UI как ошибка анализа |
| Отсутствует ключ `items` или пустой список | `parse_ai_response_to_df` | `ResponseParsingError` с понятным текстом |
| Отсутствует одно из полей у элемента | `reindex` по `EXPECTED_COLUMNS` | Поле подставляется как `None`, обработка не прерывается |
| Лишние поля у элемента | `df[EXPECTED_COLUMNS]` | Отбрасываются, в Excel не попадают |
| `characteristics` пришёл не списком, а строкой | `excel_generator` | Значение оборачивается в список из одного элемента, чтобы сериализация в ячейку не падала |
