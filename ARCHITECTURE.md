# Архитектура проекта: AI TZ Analyzer (Streamlit)

## 1. Обзор системы
Приложение на Streamlit для парсинга файлов ТЗ (.pdf, .docx), анализа текста через API GPTunneL с выбором моделей и экспорта результатов в .xlsx.

## 4. Формат обмена данными (ИИ -> Excel)

Модель обязана вернуть **только** JSON-объект (без markdown-обрамления ```json, без пояснений до/после). Системный промпт (`config.DEFAULT_SYSTEM_PROMPT`) явно это требует.

### 4.1. Схема ответа модели

```json
{
  "items": [
    {
      "item_number": 1,
      "name": "Диван двухместный",
      "characteristics": [
        "Материал обивки: искусственная кожа",
        "Цвет: чёрный"
      ],
      "max_width_mm": 1700,
      "max_depth_mm": 700,
      "max_height_mm": 850,
      "quantity": 10
    },
    {
      "item_number": 2,
      "name": "Стул для столовой",
      "characteristics": [
        "Материал каркаса: металл",
        "Материал сиденья: пластик",
        "Цвет: серый"
      ],
      "max_width_mm": null,
      "max_depth_mm": null,
      "max_height_mm": 870,
      "quantity": 120
    },
    {
      "item_number": 3,
      "name": "Пуф",
      "characteristics": [
        "Форма: квадратная",
        "Материал обивки: ткань"
      ],
      "max_width_mm": 600,
      "max_depth_mm": 600,
      "max_height_mm": 450,
      "quantity": 5
    }
  ]
}
```

### 4.2. Описание полей `items[i]`

| Поле | Тип | Обязательное | Описание |
|---|---|---|---|
| `item_number` | `int` | да | Номер позиции по порядку, присваивается моделью последовательно (1, 2, 3, …) |
| `name` | `string` | да | Наименование позиции/изделия по ТЗ (например, «Диван двухместный», «Стул для столовой») |
| `characteristics` | `array[string]` | да | Список характеристик позиции по ТЗ (материал, цвет, форма и т.п.), каждая характеристика — отдельная строка списка |
| `max_width_mm` | `int \| null` | нет | Максимальная ширина изделия в миллиметрах; `null`, если в ТЗ не указана |
| `max_depth_mm` | `int \| null` | нет | Максимальная глубина изделия в миллиметрах; `null`, если в ТЗ не указана |
| `max_height_mm` | `int \| null` | нет | Максимальная высота изделия в миллиметрах; `null`, если в ТЗ не указана |
| `quantity` | `int` | да | Требуемое количество изделий данной позиции |

Если модель не заполнила какое-то поле — `utils/excel_generator.py` подставляет `None` (пустая ячейка в Excel), а не выбрасывает исключение, чтобы не терять весь результат из-за одного неполного элемента. Поле `characteristics` — единственное поле-массив: при сериализации в Excel список объединяется в одну ячейку (каждая характеристика с новой строки внутри ячейки), чтобы сохранить читаемость и не плодить динамическое количество колонок.

### 4.3. Конвейер обработки ответа

```
raw_response (str, сырой текст от API)
        │
        ▼
_extract_json_block()   — regex вырезает { ... }, даже если модель
                           обернула ответ в ```json ... ``` или добавила текст вокруг
        │
        ▼
json.loads()             — парсинг в dict; ResponseParsingError при невалидном JSON
        │
        ▼
data["items"]             — список требований; ResponseParsingError, если отсутствует/пуст
        │
        ▼
pd.DataFrame(items)       — сырой DataFrame из списка dict
        │
        ▼
reindex по EXPECTED_COLUMNS — гарантирует фиксированный порядок и полный набор колонок
        │
        ▼
result_df (pd.DataFrame)  — источник правды: рендерится в st.dataframe/data_editor
        │                     и сериализуется в xlsx
        ▼
excel_bytes (bytes)       — итоговый файл для download_button
```

### 4.4. Результирующая таблица в Excel

Заголовки столбцов в итоговом файле переводятся на русский язык (отдельный словарь соответствия в `excel_generator.py`, на внутренние ключи JSON/DataFrame из §4.1–§4.2 это не влияет). Кроме того, между колонками «Наименование» и «Характеристики по ТЗ» добавлена колонка «Эскиз» — чисто визуальная колонка в Excel, не имеющая парного поля в ответе ИИ и в `EXPECTED_COLUMNS`: она всегда остаётся пустой (зарезервирована под будущую вставку картинки/чертежа вручную после экспорта).

| № | Наименование | Эскиз | Характеристики по ТЗ | Ширина | Глубина | Высота | Количество |
|---|---|---|---|---|---|---|---|
| 1 | Диван двухместный |  | Материал обивки: искусственная кожа<br>Цвет: чёрный | 1700 | 700 | 850 | 10 |
| 2 | Стул для столовой |  | Материал каркаса: металл<br>Материал сиденья: пластик<br>Цвет: серый |  |  | 870 | 120 |
| 3 | Пуф |  | Форма: квадратная<br>Материал обивки: ткань | 600 | 600 | 450 | 5 |

Соответствие русских заголовков внутренним полям:

| Заголовок в Excel | Внутреннее поле |
|---|---|
| № | `item_number` |
| Наименование | `name` |
| Эскиз | — (служебная колонка, всегда пустая) |
| Характеристики по ТЗ | `characteristics` |
| Ширина | `max_width_mm` |
| Глубина | `max_depth_mm` |
| Высота | `max_height_mm` |
| Количество | `quantity` |
| Объём | — (вычисляемая колонка, не хранится в DataFrame/JSON) |

Колонка «Объём» — последняя в таблице, вычисляемая: значений для неё нет ни в ответе ИИ, ни в DataFrame, вместо этого в каждую ячейку строки-позиции при генерации xlsx записывается формула Excel (а не число), которая на лету считает объём в м³ по габаритам и количеству из ячеек той же строки. Если колонки расположены в порядке из таблицы выше (A — «№», …, E — «Ширина», F — «Глубина», G — «Высота», H — «Количество», I — «Объём»), то для строки `N` формула выглядит так:

```
=ЕСЛИ(И(ЕЧИСЛО(E{N});ЕЧИСЛО(F{N});ЕЧИСЛО(G{N});ЕЧИСЛО(H{N}));(E{N}/1000)*(F{N}/1000)*(G{N}/1000)*H{N};"ПУСТО")
```

Адреса ячеек в формуле подставляются динамически по фактическому индексу столбцов «Ширина»/«Глубина»/«Высота»/«Количество» и номеру строки при генерации файла, а не хардкодятся, — если порядок колонок в `EXPECTED_COLUMNS`/`COLUMN_LABELS` изменится, формула перестроится автоматически. Формула проверяет функцией `ЕЧИСЛО`, что все четыре величины — числа (то есть ни одна из них не была пустой ячейкой из-за `null` в ответе ИИ), и только тогда считает объём как произведение габаритов, переведённых из миллиметров в метры, на количество; иначе в ячейку выводится текст `"ПУСТО"`, чтобы визуально отличать «объём не может быть посчитан» от нулевого объёма. Для строк, объединённых по позиции (несколько характеристик), формула проставляется только в первой строке диапазона объединения, как и остальные поля уровня позиции.

Особенности рендера в Excel:

- Колонка «Характеристики по ТЗ» (`characteristics`) сериализуется как многострочный текст в одной ячейке (перенос строки `\n` между элементами списка), для ячейки включается перенос по словам (`wrap_text=True`), чтобы весь список характеристик был виден без обрезки.
- Пустые «Ширина» / «Глубина» / «Высота» (значение `null` в JSON) превращаются в пустые ячейки, а не в текст `"None"` или `"null"`.
- Колонка «Эскиз» ничем не заполняется автоматически — пользователь вставляет изображение вручную в Excel после скачивания файла.
- Колонка «Объём» всегда содержит формулу Excel, а не статическое значение: при ручном редактировании ширины/глубины/высоты/количества в самом xlsx-файле пользователем объём пересчитается автоматически.
- Колонка `item_number` («№») используется как стабильный ключ при редактировании через `st.data_editor` (добавление/удаление строк не должно ломать порядок остальных).

### 4.5. Обработка ошибок формата

| Ситуация | Где ловится | Поведение |
|---|---|---|
| Модель обернула JSON в текст/markdown | `_extract_json_block` | JSON извлекается regex'ом, не падает |
| Невалидный JSON | `json.loads` | `ResponseParsingError` → показывается в UI как ошибка анализа |
| Отсутствует ключ `items` или пустой список | `parse_ai_response_to_df` | `ResponseParsingError` с понятным текстом |
| Отсутствует одно из полей у элемента | `reindex` по `EXPECTED_COLUMNS` | Поле подставляется как `None`, обработка не прерывается |
| Лишние поля у элемента | `df[EXPECTED_COLUMNS]` | Отбрасываются, в Excel не попадают |
| `characteristics` пришёл не списком, а строкой | `excel_generator` | Значение оборачивается в список из одного элемента, чтобы сериализация в ячейку не падала |
