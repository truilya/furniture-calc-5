# Архитектура проекта: AI TZ Analyzer (Streamlit)

## 1. Обзор системы
Приложение на Streamlit для парсинга файлов ТЗ (.pdf, .docx), анализа текста через API GPTunneL с выбором моделей и экспорта результатов в .xlsx.

├── config.py                   # константы: список моделей, дефолтный промпт
├── requirements.txt

## 3. Глобальное состояние (st.session_state)
Ключ	Тип	Назначение
st.session_state = {
    "uploaded_file_bytes": bytes | None,   # сырые байты файла (для кэш-парсинга)
    "uploaded_file_name": str | None,
    "extracted_text": str | None,          # текст ТЗ после парсинга

    "system_prompt": str,                  # дефолт из config, позже — редактируемый

## 4. Формат обмена данными (ИИ -> Excel)

Модель обязана вернуть **только** JSON-объект (без markdown-обрамления ```json, без пояснений до/после). Системный промпт (`config.DEFAULT_SYSTEM_PROMPT`) явно это требует.

### 4.1. Схема ответа модели

```json
{
  "items": [
    {
      "id": 1,
      "section": "Авторизация",
      "requirement": "Вход по логину и паролю",
      "description": "Пользователь должен иметь возможность войти в систему, указав email и пароль. При неверных данных показывается ошибка.",
      "priority": "Высокий"
    },
    {
      "id": 2,
      "section": "Авторизация",
      "requirement": "Восстановление пароля",
      "description": "Реализовать сброс пароля через ссылку, отправляемую на email пользователя.",
      "priority": "Средний"
    },
    {
      "id": 3,
      "section": "Профиль пользователя",
      "requirement": "Редактирование ФИО и телефона",
      "description": "В личном кабинете пользователь может изменить ФИО и номер телефона, изменения сохраняются после нажатия кнопки «Сохранить».",
      "priority": "Низкий"
    }
  ]
}
```

### 4.2. Описание полей `items[i]`

| Поле | Тип | Обязательное | Описание |
|---|---|---|---|
| `id` | `int` | да | Порядковый номер требования, присваивается моделью последовательно (1, 2, 3, …) |
| `section` | `string` | да | Название раздела/модуля ТЗ, к которому относится требование (например, «Авторизация», «Отчёты») |
| `requirement` | `string` | да | Краткая формулировка требования (заголовок строки таблицы) |
| `description` | `string` | да | Развёрнутое описание требования простыми словами, без канцеляризмов |
| `priority` | `string` | да | Приоритет требования: одно из `"Высокий"`, `"Средний"`, `"Низкий"` |

Если модель не заполнила какое-то поле — `utils/excel_generator.py` подставляет `None` (пустая ячейка в Excel), а не выбрасывает исключение, чтобы не терять весь результат из-за одного неполного элемента.

### 4.3. Конвейер обработки ответа

```
raw_response (str, сырой текст от API)
        │
        ▼
_extract_json_block()   — regex вырезает { ... }, даже если модель
                           обернула ответ в ```json ... ``` или добавила текст вокруг
        │
        ▼
json.loads()             — парсинг в dict; ResponseParsingError при невалидном JSON
        │
        ▼
data["items"]             — список требований; ResponseParsingError, если отсутствует/пуст
        │
        ▼
pd.DataFrame(items)       — сырой DataFrame из списка dict
        │
        ▼
reindex по EXPECTED_COLUMNS — гарантирует фиксированный порядок и полный набор колонок
        │
        ▼
result_df (pd.DataFrame)  — источник правды: рендерится в st.dataframe/data_editor
        │                     и сериализуется в xlsx
        ▼
excel_bytes (bytes)       — итоговый файл для download_button
```

### 4.4. Результирующая таблица в Excel

| id | section | requirement | description | priority |
|---|---|---|---|---|
| 1 | Авторизация | Вход по логину и паролю | Пользователь должен иметь возможность войти... | Высокий |
| 2 | Авторизация | Восстановление пароля | Реализовать сброс пароля через ссылку... | Средний |
| 3 | Профиль пользователя | Редактирование ФИО и телефона | В личном кабинете пользователь может изменить... | Низкий |

Колонка `id` в дальнейшем используется как стабильный ключ при редактировании через `st.data_editor` (добавление/удаление строк не должно ломать порядок остальных).

### 4.5. Обработка ошибок формата

| Ситуация | Где ловится | Поведение |
|---|---|---|
| Модель обернула JSON в текст/markdown | `_extract_json_block` | JSON извлекается regex'ом, не падает |
| Невалидный JSON | `json.loads` | `ResponseParsingError` → показывается в UI как ошибка анализа |
| Отсутствует ключ `items` или пустой список | `parse_ai_response_to_df` | `ResponseParsingError` с понятным текстом |
| Отсутствует одно из полей у элемента | `reindex` по `EXPECTED_COLUMNS` | Поле подставляется как `None`, обработка не прерывается |
| Лишние поля у элемента | `df[EXPECTED_COLUMNS]` | Отбрасываются, в Excel не попадают |
