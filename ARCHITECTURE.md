# Архитектура проекта: AI TZ Analyzer (Streamlit)

## 1. Обзор системы
Приложение на Streamlit для парсинга файлов ТЗ (.pdf, .docx), анализа текста через API GPTunneL с выбором моделей и экспорта результатов в .xlsx.

## 4. Формат обмена данными (ИИ -> Excel)

Модель обязана вернуть **только** JSON-объект (без markdown-обрамления ```json, без пояснений до/после). Системный промпт (`config.DEFAULT_SYSTEM_PROMPT`) явно это требует.

### 4.1. Схема ответа модели

```json
{
  "items": [
    {
      "item_number": 1,
      "name": "Диван двухместный",
      "characteristics": [
        "Материал обивки: искусственная кожа",
        "Цвет: чёрный"
      ],
      "max_width_mm": 1700,
      "max_depth_mm": 700,
      "max_height_mm": 850,
      "quantity": 10
    },
    {
      "item_number": 2,
      "name": "Стул для столовой",
      "characteristics": [
        "Материал каркаса: металл",
        "Материал сиденья: пластик",
        "Цвет: серый"
      ],
      "max_width_mm": null,
      "max_depth_mm": null,
      "max_height_mm": 870,
      "quantity": 120
    },
    {
      "item_number": 3,
      "name": "Пуф",
      "characteristics": [
        "Форма: квадратная",
        "Материал обивки: ткань"
      ],
      "max_width_mm": 600,
      "max_depth_mm": 600,
      "max_height_mm": 450,
      "quantity": 5
    }
  ]
}
```

### 4.2. Описание полей `items[i]`

| Поле | Тип | Обязательное | Описание |
|---|---|---|---|
| `item_number` | `int` | да | Номер позиции по порядку, присваивается моделью последовательно (1, 2, 3, …) |
| `name` | `string` | да | Наименование позиции/изделия по ТЗ (например, «Диван двухместный», «Стул для столовой») |
| `characteristics` | `array[string]` | да | Список характеристик позиции по ТЗ (материал, цвет, форма и т.п.), каждая характеристика — отдельная строка списка |
| `max_width_mm` | `int \| null` | нет | Максимальная ширина изделия в миллиметрах; `null`, если в ТЗ не указана |
| `max_depth_mm` | `int \| null` | нет | Максимальная глубина изделия в миллиметрах; `null`, если в ТЗ не указана |
| `max_height_mm` | `int \| null` | нет | Максимальная высота изделия в миллиметрах; `null`, если в ТЗ не указана |
| `quantity` | `int` | да | Требуемое количество изделий данной позиции |

Если модель не заполнила какое-то поле — `utils/excel_generator.py` подставляет `None` (пустая ячейка в Excel), а не выбрасывает исключение, чтобы не терять весь результат из-за одного неполного элемента. Поле `characteristics` — единственное поле-массив: при сериализации в Excel список объединяется в одну ячейку (каждая характеристика с новой строки внутри ячейки), чтобы сохранить читаемость и не плодить динамическое количество колонок.

### 4.3. Конвейер обработки ответа

```
raw_response (str, сырой текст от API)
        │
        ▼
_extract_json_block()   — regex вырезает { ... }, даже если модель
                           обернула ответ в ```json ... ``` или добавила текст вокруг
        │
        ▼
json.loads()             — парсинг в dict; ResponseParsingError при невалидном JSON
        │
        ▼
data["items"]             — список требований; ResponseParsingError, если отсутствует/пуст
        │
        ▼
pd.DataFrame(items)       — сырой DataFrame из списка dict
        │
        ▼
reindex по EXPECTED_COLUMNS — гарантирует фиксированный порядок и полный набор колонок
        │
        ▼
result_df (pd.DataFrame)  — источник правды: рендерится в st.dataframe/data_editor
        │                     и сериализуется в xlsx
        ▼
excel_bytes (bytes)       — итоговый файл для download_button
```

### 4.4. Результирующая таблица в Excel

Итоговый xlsx формируется по **JSON-шаблону** `templates/excel_template.json`. Шаблон загружается в `config.py` в константу `EXCEL_TEMPLATE`, из него же выводятся `EXPECTED_COLUMNS`, `COLUMN_LABELS` и `COLUMN_GROUPS`. Код `utils/excel_generator.py` не знает конкретных полей: колонки, их порядок, заголовки, группы, формулы, верхние и нижние служебные строки берутся только из шаблона. Чтобы добавить, убрать или переставить колонку, достаточно изменить шаблон (а если поле приходит от ИИ, то и `DEFAULT_SYSTEM_PROMPT`), код менять не нужно.

Заголовки колонок в Excel русские, они задаются в шаблоне (`label`). На внутренние ключи JSON/DataFrame из §4.1–§4.2 это не влияет.

Внешний вид таблицы (для примера из §4.1):

| № | Наименование | Эскиз | Характеристики по ТЗ | Ширина | Глубина | Высота | Количество | Объём | Цена по ТЗ | Сумма по ТЗ | Цена по эскизу | Сумма по эскизу | Заполнение |
|---|---|---|---|---|---|---|---|---|---|---|---|---|---|
| 1 | Диван двухместный | | Материал обивки: искусственная кожа / Цвет: чёрный | 1700 | 700 | 850 | 10 | 11.9 | 15000 | 178500 | | | Заполнено |
| 2 | Стул для столовой | | Материал каркаса: металл / Материал сиденья: пластик / Цвет: серый | | | 870 | 120 | | | | | | ПУСТО |
| 3 | Пуф | | Форма: квадратная / Материал обивки: ткань | 600 | 600 | 450 | 5 | 0.81 | | | 5500 | 4455 | Заполнено |

Над шапкой расположена строка «общее количество из ЕИС →» с пустой ячейкой ручного ввода над колонкой «Количество». Над колонками «Цена по ТЗ» и «Сумма по ТЗ» объединённый заголовок «Вариант 1», над «Цена по эскизу» и «Сумма по эскизу» — «Вариант 2». Под таблицей строка «проверка общего количества →» с формулой сравнения. Каждая характеристика позиции занимает отдельную строку, а ячейки уровня позиции объединяются по вертикали.

#### 4.4.1. Структура шаблона

Корневые ключи:

| Ключ | Тип | Описание |
|---|---|---|
| `sheet_name` | string | Название листа |
| `top_rows` | array | Строки над шапкой (необязательно) |
| `columns` | array | Колонки слева направо (обязательно) |
| `footer_rows` | array | Строки под таблицей (необязательно) |

Поля колонки (`columns[i]`):

| Поле | Обязательное | Описание |
|---|---|---|
| `key` | да | Внутреннее имя колонки, уникальное. Для `source: "ai"` совпадает с ключом в ответе модели |
| `label` | да | Заголовок колонки в Excel |
| `source` | да | `ai` — значение из ответа модели; `manual` — пустая колонка, заполняется пользователем в Excel; `formula` — формула Excel из поля `formula` |
| `formula` | для `formula` | Формула с плейсхолдерами (см. ниже) |
| `group` | нет | Название общего заголовка над соседними колонками с одинаковым `group` |
| `type` | нет | `list` — значение является массивом строк, каждый элемент выводится в отдельной строке |
| `item_level` | нет | По умолчанию `true`: ячейки колонки объединяются по вертикали, если у позиции несколько строк. Для `type: "list"` задаётся `false` |
| `wrap` | нет | Перенос по словам в ячейке |
| `width` | нет | Ширина колонки; если не задана, подбирается по содержимому |
| `number_format` | нет | Числовой формат Excel |

Поля `top_rows[i]`: `id` (идентификатор, на него ссылается `{@id}`), `label` (подпись, объединяется до колонки `input_column`), `input_column` (ключ колонки, над которой остаётся пустая ячейка ввода).

Поля `footer_rows[i]`: `label` (подпись), `value_column` (ключ колонки, в которой выводится результат), `formula` (формула).

Плейсхолдеры в формулах:

| Плейсхолдер | Значение |
|---|---|
| `{key}` | Ячейка колонки `key` в текущей строке позиции (например, `E4`) |
| `{key:range}` | Диапазон данных колонки `key` (например, `H4:H10`) |
| `{@id}` | Абсолютный адрес ячейки ввода из `top_rows` с этим `id` (например, `$H$1`) |

Неизвестный ключ в формуле приводит к `TemplateError` с понятным текстом.

Пример шаблона по умолчанию:

```json
{
```

#### 4.4.2. Колонки по умолчанию и формулы

Соответствие заголовков внутренним полям:

| Заголовок в Excel | Внутреннее поле |
|---|---|
| № | `item_number` |
| Наименование | `name` |
| Эскиз | `sketch` (служебная, всегда пустая) |
| Характеристики по ТЗ | `characteristics` |
| Ширина | `max_width_mm` |
| Глубина | `max_depth_mm` |
| Высота | `max_height_mm` |
| Количество | `quantity` |
| Объём | `volume` (формула) |
| Цена по ТЗ | `tz_price` (служебная, заполняется вручную) |
| Сумма по ТЗ | `tz_sum` (формула) |
| Цена по эскизу | `sketch_price` (служебная, заполняется вручную) |
| Сумма по эскизу | `sketch_sum` (формула) |
| Заполнение | `fill_status` (формула) |

Колонки `source: "manual"` и `source: "formula"` в ответе ИИ не приходят. В DataFrame они присутствуют пустыми, формулы проставляются только при генерации xlsx.

Формулы записываются в первую строку каждой позиции (для объединённых строк — только в первую строку диапазона). Для строки `N` при порядке колонок из шаблона по умолчанию (E — «Ширина», F — «Глубина», G — «Высота», H — «Количество», I — «Объём») формула объёма в м³ выглядит так:

```
=IF(AND(ISNUMBER(E{N}),ISNUMBER(F{N}),ISNUMBER(G{N}),ISNUMBER(H{N})),(E{N}/1000)*(F{N}/1000)*(G{N}/1000)*H{N},"")
```

Формулы сознательно хранятся с английскими именами функций (`IF`, `AND`, `ISNUMBER`, `SUM`) и запятой в качестве разделителя аргументов: формат `.xlsx` (OOXML) хранит формулы во внутреннем представлении, а локализованные имена функций и `;` — это только то, как Excel показывает их в интерфейсе при русской локали. `openpyxl` записывает строку «как есть»: формула с русскими именами показывалась бы как `#ИМЯ?`. Пользователь с русским Excel увидит привычные `ЕСЛИ`, `И`, `ЕЧИСЛО` и `;`.

Адреса ячеек подставляются по плейсхолдерам динамически, исходя из реального порядка колонок в шаблоне и номера строки, а не хардкодятся. Если порядок колонок в шаблоне изменится, формулы перестроятся автоматически. Если хотя бы одна из четырёх величин не число (в ответе ИИ было `null`), формула возвращает пустую строку `""`, а не `0`.

#### 4.4.3. Группы «Вариант 1» и «Вариант 2»

Колонки с одинаковым значением `group` объединяются общим заголовком в верхней строке шапки (`merge_cells`). Колонки без `group` объединяют обе строки шапки по вертикали.

- **«Вариант 1»**: «Цена по ТЗ», «Сумма по ТЗ».
- **«Вариант 2»**: «Цена по эскизу», «Сумма по эскизу».

«Цена по ТЗ» и «Цена по эскизу» — пустые ячейки: пользователь вписывает цену вручную после получения файла. «Сумма по ТЗ» и «Сумма по эскизу» — формулы, которые возвращают `""`, если «Объём» или соответствующая цена не заполнены (чтобы не показывать обманчивый `0`):

```
Сумма по ТЗ:      =IF(AND(ISNUMBER(I{N}),ISNUMBER(J{N})),I{N}*J{N},"")
Сумма по эскизу:  =IF(AND(ISNUMBER(I{N}),ISNUMBER(L{N})),I{N}*L{N},"")
```

(`I` — «Объём», `J` — «Цена по ТЗ», `L` — «Цена по эскизу»; буквы вычисляются по шаблону).

Колонка «Заполнение» выводит `"ПУСТО"`, только если обе суммы пусты, иначе `"Заполнено"`:

```
=IF(AND(K{N}="",M{N}=""),"ПУСТО","Заполнено")
```

(`K` — «Сумма по ТЗ», `M` — «Сумма по эскизу»). Проверка `=""` отличает пустую строку от заполненного значения, включая `0`, если пользователь явно ввёл нулевую цену.

#### 4.4.4. Верхняя и нижняя строки

Строка из `top_rows` («общее количество из ЕИС →») расположена над шапкой: подпись выровнена вправо и объединена до колонки `input_column`, в самой ячейке над этой колонкой пользователь вручную вводит общее количество из ЕИС.

Строка из `footer_rows` («проверка общего количества →») расположена под таблицей. Формула сравнивает значение из ячейки ввода с суммой всей колонки «Количество»:

```
=IF($H$1=SUM(H4:H10),"Всё ОК","Ошибка!")
```

Суммируется весь диапазон данных, так как у объединённых строк одной позиции количество записано только в первой строке, а остальные ячейки пусты.

#### 4.4.5. Особенности рендера

- Колонка с `type: "list"` («Характеристики по ТЗ») выводится по одному элементу списка в строке; для ячеек включается перенос по словам (`wrap_text=True`) и выравнивание по верхнему краю.
- Колонки с `item_level: true` объединяются по вертикали на все строки позиции. Границы позиции определяются по самому DataFrame: строка, в которой все скалярные поля пусты, а элемент списка заполнен, считается продолжением предыдущей позиции. Поэтому объединение работает и после редактирования в `st.data_editor`, не требуя служебных атрибутов `df.attrs`.
- Пустые значения (`null` в JSON) превращаются в пустые ячейки, а не в текст `"None"` или `"null"`.
- Колонки `source: "manual"` («Эскиз», «Цена по ТЗ», «Цена по эскизу») ничем не заполняются автоматически.
- Колонки `source: "formula"` содержат формулы Excel, а не числа: при ручном изменении габаритов, количества или цен значения пересчитываются автоматически.
- Колонка `item_number` («№») служит стабильным ключом при редактировании через `st.data_editor` (добавление и удаление строк не должно ломать порядок остальных).

### 4.5. Обработка ошибок формата

| Ситуация | Где ловится | Поведение |
|---|---|---|
| Модель обернула JSON в текст/markdown | `_extract_json_block` | JSON извлекается regex'ом, не падает |
| Невалидный JSON | `json.loads` | `ResponseParsingError` → показывается в UI как ошибка анализа |
| Отсутствует ключ `items` или пустой список | `parse_ai_response_to_df` | `ResponseParsingError` с понятным текстом |
| Отсутствует одно из полей у элемента | `reindex` по `EXPECTED_COLUMNS` | Поле подставляется как `None`, обработка не прерывается |
| Лишние поля у элемента | `df[EXPECTED_COLUMNS]` | Отбрасываются, в Excel не попадают |
| `characteristics` пришёл не списком, а строкой | `excel_generator` | Значение оборачивается в список из одного элемента, чтобы сериализация в ячейку не падала |
